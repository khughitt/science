# Proposition Reconciliation (Phase 4e, Half A) - Design

**Date:** 2026-06-30
**Status:** Design approved in brainstorming; awaiting implementation plan.
**Kind:** Feature design. Phase 4e of the lit-annot / sub-article-annotation arc.
**Predecessors:** 4a statement-to-proposition promotion, 4b question/hypothesis promotion,
4c proposition reasoning synthesis, 4d cross-paper literature evidence.

> **Scope note.** Phase 4d Half A made separately promoted assertions contribute
> literature evidence to a shared proposition. Phase 4e Half A does not change belief
> aggregation. It finds likely proposition identity/factorization reconciliation work
> and produces reviewed judgments. A later apply phase can consume approved judgments
> to canonicalize proposition identities, move provenance, update sidecars, and archive
> or redirect duplicates.

---

## 1. Goal and scope

Phase 4e is the reviewed reconciliation layer over the proposition spine built in
4a-4d.

**Goal:** surface cases where the current proposition graph is probably split or
semantically inconsistent, then produce curator-reviewed reconciliation judgments that
later phases can safely apply. It closes the gap 4a intentionally left open: exact-title
promotion catches identical claims, but paraphrases and different factorizations can
still become separate belief-bearing propositions.

There are two lanes.

### Lane A: same-claim candidate groups

Find separate `proposition:*` entities that may actually be the same truth-apt claim.
These are under-linked propositions, usually caused by paraphrase, title variation, or
different 4c factorizations. The output is a candidate group for review, not a merge.

### Lane B: same-proposition factorization disagreement

Find one already-linked proposition whose contributing paper statements imply divergent
factorizations or stances. The output is a diagnostic review item: the proposition
identity may be right, but its 4c reasoning fields may need resynthesis, a note, or
split review.

In scope:

- deterministic candidate generation;
- explainable blocking/scoring signals;
- agent review scaffold;
- reviewed judgment file validation;
- diagnostics over `meta` / real corpora;
- no graph or belief engine changes.

Out of scope:

- automatic canonicalization or merge;
- updating sidecar `promoted_to`;
- moving `source_refs`;
- archiving duplicate propositions;
- embeddings as a required dependency;
- citation-graph independence;
- changing 4d belief aggregation.

The important epistemic boundary: 4e may say "these look like the same claim" or "this
proposition's factorization is contested", but it does not change what belief aggregates
over. A later apply phase can consume approved judgments.

## 2. Data model and artifacts

4e introduces one derived review artifact and one validated reviewed artifact. It does
not add proposition frontmatter fields in Half A.

### Candidate report, generated by Python

A new read-only command produces deterministic candidates:

```bash
science annotate reconcile-propositions --all --format table|json|scaffold
science annotate reconcile-propositions --proposition proposition:<id> --format json|scaffold
science annotate reconcile-propositions --source entities/papers/<paper>.source.md --format json|scaffold
```

The JSON report has two top-level candidate arrays:

```json
{
  "same_claim_candidates": [],
  "factorization_disagreements": [],
  "summary": {}
}
```

Each same-claim candidate is a group, not only a pair, so transitive near-duplicates can
be reviewed together:

```json
{
  "candidate_id": "reconcile:same-claim/<sha256>",
  "propositions": ["proposition:a", "proposition:b"],
  "priority": "high",
  "splittable": false,
  "review_coverage_required": true,
  "signals": {
    "title_token_jaccard": 0.82,
    "same_subject": true,
    "same_object": true,
    "predicate_compatible": true,
    "polarity_compatible": true,
    "shared_source_papers": []
  },
  "explanation": [
    "same subject/object",
    "compatible predicate/polarity",
    "high title token overlap"
  ]
}
```

Each factorization disagreement is keyed to one proposition:

```json
{
  "candidate_id": "reconcile:factorization/<sha256>",
  "proposition": "proposition:x",
  "priority": "medium",
  "papers": ["paper:A", "paper:B"],
  "current": {
    "subject": "...",
    "predicate": "affects",
    "object": "...",
    "polarity": "positive",
    "claim_layer": "causal_effect"
  },
  "observed_statement_hints": [
    {
      "paper": "paper:A",
      "annotation": "annotation:...#s1",
      "stance": "asserted",
      "section": "results",
      "subject": "...",
      "object": "...",
      "subject_concept": null,
      "object_concept": null,
      "exact": "..."
    }
  ],
  "disagreement": ["object differs", "stance mix requires review"],
  "recommended_action": "factorization_needs_resynthesis"
}
```

### Reviewed judgment file, authored by agent plus curator

The scaffold is agent-facing JSON. The reviewed output is durable project curation
state, validated by Python but not applied in Half A:

```json
{
  "source": "llm-review:<model>:proposition-reconcile-v1",
  "judgments": [
    {
      "candidate_id": "reconcile:same-claim/<sha256>",
      "judgment_id": "reconcile:judgment/<sha256>",
      "lane": "same_claim",
      "decision": "same_claim",
      "canonical_proposition": "proposition:a",
      "members": ["proposition:a", "proposition:b"],
      "rationale": "Both assert the same signed relation over the same endpoints; wording differs only in mechanism detail.",
      "confidence": "high"
    }
  ]
}
```

For factorization diagnostics:

```json
{
  "candidate_id": "reconcile:factorization/<sha256>",
  "judgment_id": "reconcile:judgment/<sha256>",
  "lane": "factorization_disagreement",
  "decision": "factorization_needs_resynthesis",
  "proposition": "proposition:x",
  "rationale": "The current proposition is factored as BRCA1 loss -> genomic instability, but two supporting papers target replication stress specifically.",
  "confidence": "medium"
}
```

Closed decision vocabulary:

- `same_claim`;
- `related_but_distinct`;
- `conflict_or_negation`;
- `factorization_needs_resynthesis`;
- `stance_review_needed`;
- `split_possible`;
- `insufficient_hints`;
- `needs_human`.

Closed confidence vocabulary:

- `high`;
- `medium`;
- `low`.

Candidate reports are derived and disposable. Reviewed judgments are durable curation
handoff state, but they are not evidence lines and do not affect belief in Half A.
The `llm-review:<model>:proposition-reconcile-v1` source convention is new in 4e,
modeled on 4c's `llm-synth:<model>:proposition-synthesize-v1` pattern but validated
by a separate 4e validator.

## 3. Candidate generation

Candidate generation is deterministic, conservative, and explainable. Python proposes
review work; it does not decide truth.

### Lane A: same-claim candidate groups

Inputs per proposition:

- `id`, `title`, and body claim text when available;
- `subject`, `predicate`, `object`, `polarity`, `claim_layer`, `identification_strength`;
- `source_refs` paper and annotation refs;
- 4d literature assertions from `scan_literature_assertions`;
- belief summary as context only, not as a merge signal.

Blocking requires at least one strong structural signal before any looser lexical signal
counts.

Strong structural signals:

- same normalized `(subject, predicate, object)` with compatible polarity;
- same normalized `(subject, object)` with compatible predicate family;
- same paper/annotation provenance pattern points to separate proposition ids;
- one proposition's title is a normalized substring/restatement of another and endpoints
  match.

Lexical signals:

- title token Jaccard / containment;
- normalized claim text overlap;
- shared high-information tokens after stopword removal;
- optional later embedding similarity, but no embedding dependency in Half A.

Predicate compatibility is intentionally small and tied to the existing model enum:

- exact predicate equality is compatible;
- two predicates in `SIGN_MEANINGFUL_PREDICATES` (`affects`, `regulates`,
  `associates_with`) are weakly compatible when subject/object match and polarity is
  compatible;
- sign-less predicates are compatible only by exact predicate equality. In particular,
  `subtype_of` and `part_of` are not interchangeable, and `induces_state` /
  `transitions_to` are not treated as a family in Half A.

Compatibility rules:

- same polarity or one side `unsigned` is compatible;
- `positive` versus `negative` is not same-claim by default, but may create
  `conflict_or_negation` review if subject/object/predicate match;
- sign-less predicates require `not_applicable`;
- missing fields do not block candidacy if lexical/provenance signals are strong, but
  they lower priority and mark the candidate as `needs_factorization_context`.

Grouping:

- build candidate edges between propositions from explicit blocking buckets, not a full
  project-wide pairwise sweep. Initial bucket keys are normalized
  `(subject, predicate, object)`, normalized `(subject, object)`, source paper, and
  high-information title tokens;
- connected components become review groups;
- `candidate_id = reconcile:same-claim/<sha256>` over sorted proposition refs plus
  candidate lane;
- pair candidates are `splittable: false`; groups of three or more are
  `splittable: true` so review can mark only a subset as `same_claim` when the
  connected component joined through a weaker bridge;
- same-claim `candidate_id` canonical key:
  `same_claim\0<ref1>\0<ref2>...`, where refs are sorted canonical ids and the digest
  is the full SHA-256 hex;
- durable `judgment_id` canonical key:
  `<lane>\0<decision>\0<sorted judged member refs or proposition ref>`. For
  same-claim judgments, the judged member set is the member set the reviewer actually
  ruled on, not necessarily the full generated component;
- splittable components require coverage: every member in the generated component must
  appear in at least one reviewed judgment for that `candidate_id`, even if the decision
  is `related_but_distinct` or `needs_human`. This avoids silent fall-through for
  excluded members;
- very large components become `component-too-large` faults with member ids instead of
  unreadable scaffold payloads. Half A uses `MAX_RECONCILIATION_COMPONENT_SIZE = 25`;
  larger components are reported and skipped from scaffold generation.

### Lane B: factorization disagreement

Inputs come from already unified propositions and their active promoted annotations.

Detect when a single proposition has:

- mixed derived stances across papers or same-paper contested groups from 4d;
- multiple source annotations whose statement JSON carries incompatible `subject` /
  `object` hints;
- current 4c fields inconsistent with most contributing statement hints;
- current proposition is unfactored despite multiple promoted assertions with useful
  hints.

This lane does not propose `same_claim`. It emits one diagnostic item with a recommended
action:

- `factorization_needs_resynthesis`;
- `stance_review_needed`;
- `split_possible`;
- `insufficient_hints`.

These recommended actions are also valid reviewed decisions for Lane B, so the reviewer
can preserve the distinction surfaced by the generator.

### Priority

Use transparent priority rather than opaque model scores:

- `high`: exact/normalized structured match, or identical source accidentally split;
- `medium`: endpoint match plus high lexical overlap;
- `low`: lexical-only or missing-factorization candidates.

The agent scaffold includes raw signals and excerpts, so review can disagree with the
deterministic priority.

## 4. Agent review scaffold and validation

4e follows the 4c brain/hands split: Python prepares bounded context, an agent makes the
semantic judgment, and Python validates the reviewed output.

### Scaffold

The scaffold is agent-facing JSON with:

- candidate id;
- candidate lane: `same_claim` or `factorization_disagreement`;
- proposition frontmatter snapshots;
- titles and claim/body snippets;
- source papers and annotation refs;
- statement exact spans and stance;
- 4c factorizations;
- deterministic signals and priority;
- explicit instruction to choose only from listed propositions and never invent refs.

The scaffold is read-only. It is regenerated from the current corpus whenever needed.

### Validation

Python validates reviewed files with fail-loud semantics:

- top-level `source` must match
  `^llm-review:[A-Za-z0-9._-]+:proposition-reconcile-v1$`;
- every `candidate_id` must exist in the current generated candidate set, except that a
  same-claim judgment over a splittable subset may remain valid when its judged
  `members` are still a subset of the current component and still satisfy at least one
  current candidate edge among themselves. Churn in excluded members does not
  invalidate the subset judgment;
- `judgment_id` must equal the deterministic hash for the lane, decision, and judged
  member/proposition set;
- `lane` must match the candidate's lane;
- `decision` must be from the closed vocabulary;
- `same_claim` is valid only for Lane A; Lane B accepts
  `factorization_needs_resynthesis`, `stance_review_needed`, `split_possible`,
  `insufficient_hints`, or `needs_human`;
- `members` must be exactly the candidate group, or a subset only when the candidate group
  was explicitly marked splittable;
- for a splittable same-claim group, the reviewed file must cover every generated member
  through at least one judgment for that candidate id;
- `canonical_proposition` is required for `same_claim` and must be one of `members`;
- `canonical_proposition` is forbidden for non-merge decisions;
- factorization decisions must name the single proposition in the candidate;
- `confidence` must be `high`, `medium`, or `low`;
- `rationale` is required and non-empty.

Validation writes nothing to proposition files. It only confirms that the reviewed
artifact is coherent and current. Non-splittable stale `candidate_id`s fail, forcing
regeneration/review rather than silently accepting obsolete judgments. Splittable subset
judgments are durable over the member set actually ruled on, so unrelated membership
churn in the larger component does not invalidate the review.

## 5. Integration points

- Reuse `scan_literature_assertions` from 4d for active promoted statement provenance and
  stance. Do not re-parse sidecars separately. To make Lane B buildable, 4e extends the
  shared 4d `LiteratureAssertion` dataclass with behavior-neutral appended fields:
  `statement_exact`, `section`, `subject`, `object`, `subject_concept`, and
  `object_concept`. The scanner already has the annotation in hand; it should parse the
  statement JSON once into this richer assertion record instead of having reconciliation
  re-open sidecars with a second parser.
- Reuse proposition loading via `load_project_sources` / `PropositionEntity` so candidate
  generation sees the same canonical ids and source refs as materialize/validate.
- Reuse 4c synthesis fields as structured comparison signals; do not add new proposition
  frontmatter in Half A.
- Add one CLI surface under `science annotate`, because this is part of the lit-annot /
  promotion arc:

```bash
science annotate reconcile-propositions --all --format table|json|scaffold
science annotate reconcile-propositions --proposition proposition:<id> --format json|scaffold
science annotate reconcile-propositions --source entities/papers/<paper>.source.md --format json|scaffold
science annotate validate-proposition-reconciliation --input path/to/review.json
```

The validation command is a flat `annotate` sibling, not a nested subcommand, matching the
existing `validate-prose-decomposition-artifact` convention.

## 6. Error handling

Candidate generation is report-mode by default:

- stale/corrupt 4d assertions are surfaced as faults and excluded from candidate
  evidence;
- malformed proposition frontmatter already fails through project loading;
- invalid/missing reasoning fields are not faults; they are signals for lower-priority
  review;
- giant candidate components are emitted as `component-too-large` faults with member ids,
  not dumped into an unusable scaffold;
- unknown refs in reviewed files fail validation.

The 4e reviewed-file validator is strict because the review file is a future apply input.

## 7. Testing

Focused tests:

- structured match proposes a high-priority same-claim group;
- positive versus negative same endpoints becomes `conflict_or_negation`, not
  `same_claim`;
- missing factorization still yields a lower-priority candidate when lexical/provenance
  signals are strong;
- connected components group deterministic pairs into stable candidate ids;
- large component is faulted/capped deterministically;
- same proposition with incompatible statement hints emits a factorization diagnostic;
- reviewed file validation accepts a valid `same_claim` judgment;
- validation rejects stale candidate ids, invented proposition refs, wrong-lane decisions,
  missing rationale, and bad source strings;
- CLI JSON/scaffold shapes are stable;
- real-corpus smoke over `meta` reports candidates/faults without writing entities.

## 8. Non-goals

- no merge/apply;
- no `same_as`, alias, archive, or sidecar rewrite;
- no belief aggregation changes;
- no embedding dependency;
- no automatic 4c resynthesis;
- no identification-strength promotion.

## 9. Later apply phase

A later phase can consume approved `same_claim` judgments to perform canonicalization:

- choose one survivor proposition;
- move source refs to the survivor;
- update sidecar `promoted_to` backlinks;
- redirect or archive duplicate propositions;
- decide whether reviewed factorization diagnostics trigger 4c resynthesis, split, or
  curator notes.

That mutation layer is deliberately excluded from 4e Half A. Keeping Half A
candidate/review-only prevents premature claim merges while still creating durable,
validated curation state for the eventual apply workflow.
