# Task Inquiry Surface Guidance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tighten the active command guidance for tasks, next-steps, hypotheses, and inquiry/model authoring so agents choose the durable source surface instead of stale graph mutation or transient planning artifacts.

**Architecture:** This is a docs-first, behavior-preserving cleanup. Guard tests in `science/tests/test_command_docs.py` and `science/tests/test_codex_skills.py` pin the intended wording, source command docs are updated, and generated `codex-skills/` mirrors are regenerated from those sources.

**Tech Stack:** Markdown command docs, generated Codex skill mirrors, Python `pytest` doc guard tests, existing `scripts/generate_codex_skills.py`.

---

## Source Design

Implement the first cleanup slice from `docs/audits/framework-surface/task-inquiry-surface-design.md`.

Key design decisions for this plan:

- `next-steps` remains a recommendation and synthesis workflow; accepted work becomes `science tasks ...` records only after user acceptance.
- `sketch-model` should not present `science graph add concept ...` as durable inquiry authoring. Direct graph mutation writes to `knowledge/graph.trig`, which graph materialization rebuilds from sources.
- `specify-model` may still mention direct graph concept writes only as exploratory/non-durable and only after telling inquiry-patch users to edit `entities/patches/<slug>.md`.
- `add-hypothesis` should keep the CLI lifecycle first: create with `science hypotheses create`, then use templates to write the body without replacing CLI-owned frontmatter.
- `questions reserve` stays local to parallel paper-review guidance in this slice; it is already accurately documented as a concurrency exception.

## File Structure

- Modify `science/tests/test_command_docs.py`: add a whitespace-normalizing helper for prose guards, plus source-doc guard tests for the next-steps boundary, sketch-model source-first inquiry authoring, specify-model non-durable direct graph writes, and add-hypothesis CLI-first lifecycle.
- Modify `science/tests/test_codex_skills.py`: add a whitespace-normalizing helper for prose guards, plus committed generated-skill guard tests for the same source-doc behaviors so stale `codex-skills/` mirrors fail tests.
- Modify `commands/next-steps.md`: add a concise boundary statement near the top of setup.
- Modify `commands/sketch-model.md`: replace durable `science graph add concept` instructions with source-first inquiry patch guidance.
- Modify `commands/specify-model.md`: mark direct `science graph add concept` use as exploratory/non-durable and point inquiry-patch projects to source editing.
- Modify `commands/add-hypothesis.md`: reorder setup/writing guidance so CLI creation owns lifecycle and templates are only body-writing references after creation.
- Regenerate `codex-skills/`: run the existing generator so `science-next-steps`, `science-sketch-model`, `science-specify-model`, and `science-add-hypothesis` match source command docs.
