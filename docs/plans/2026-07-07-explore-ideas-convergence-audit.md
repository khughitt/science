# Explore-Ideas Convergence Representation Audit

Date: 2026-07-07
Status: implemented

## Feedback Item

`fb-2026-07-04-005`: No representation for candidates independently generated by two lenses; forces keep-one.

## Finding

The current toolkit already has the needed representation:

- `commands/explore-ideas.md` instructs Phase 3 to detect convergence and Phase 4 to emit one candidate block with multiple `lens_views`.
- `science explore-ideas apply` persists multi-lens `origins` and `lens_views` onto the created entity.
- `science-model` validates `lens_views`: one view per lens, unique non-null origin refs, and each `origin_ref` matching one of the entity's own origin refs.
- Graph materialization reifies lens views and links each view to its lens and origin.
- `science validate` warns when an explore-ideas lens origin exists without `lens_views`.
- `science explore-ideas backfill-lens-views` can recover views from older applied reports.
- `science explore-ideas gaps` reports `missing_lens_views` for applied candidates whose entity lost the view metadata.

## Change In This Branch

This branch does not add a new data model. It makes the implemented model durable and discoverable:

- `docs/user-guide/entities.md` now documents `origins`, `lens_views`, and `added_by` for explore-ideas output.
- The guide explicitly says convergent ideas should be represented as one entity with multiple `lens_views`, not duplicate entities per lens.
- Command-doc, committed Codex skill, and user-guide tests now guard the convergence representation.

## Non-Goals

- No new apply behavior.
- No new entity fields.
- No change to belief aggregation; lens convergence records discovery provenance, not evidential support.
